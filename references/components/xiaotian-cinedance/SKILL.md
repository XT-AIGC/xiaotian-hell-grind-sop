# xiaotian-CINEDANCE

把角色表演与导演调度编译成同一条可执行的 Seedance 2.0 提示词。核心原则：**人物先在压力下采取行动，摄影机再选择最能看见这个行动及其后果的位置。**

默认直接输出简体中文成品提示词。除非用户明确要求分析、解释、QA、变体、英文或双语，不输出内部推导、检查清单或英文草稿。

## 读取模块

开始任何任务前，先读 `references/integration-rules.md`。

按镜头内容加载：

| 当前任务 | 必读文件 |
|---|---|
| 有人物、动物拟人角色或可表演主体 | `references/acting-performance-system.md`、`references/cinedance-directing-system.md` |
| 无人空镜、纯环境、纯产品或纯物理过程 | `references/cinedance-directing-system.md`，跳过表演模块 |
| 需要固定输出骨架或控制长度 | `templates/final-seedance-prompt-template.md` |
| 需要查看融合方式 | `examples/integrated-dialogue-shot.md` |

不要把模块全文复制进结果。读取规则后，只保留当前镜头真正可见、可听、可执行的内容。

## 输入处理

只提取当前镜头或当前受控序列：

- 当前出镜人物与原样保留的 `@引用标签`
- 地点、道具、车辆、动物及其当前状态
- 时长、画幅、模式和参考素材；已由平台界面确定的参数不重复写
- 当前戏剧事件、对白、声音要求和禁止事项
- 首帧、末帧、人物位置、视线、轴线和连续性要求
- 已批准的角色母版、实际验收末帧或项目连续性记录

删除不属于当前镜头的场次号、旧角色、旧标签、上一场摘要和“和之前一样”等依赖模型猜测的表述。不得编造用户没有提供的参考标签、素材内容或已生成结果。

## 工作流

### 1. 确定镜头任务

用一句内部工作句明确：这个镜头要让观众看见谁为了什么，在什么压力下采取什么行动，并在结尾发生什么可见变化。

若一个短镜头承载不了全部事件，先压缩成一个核心动作；只有用户要求多镜头或单机位无法清楚呈现时才设计受控切镜。

### 2. 构建表演引擎

对每个当前出镜的主要人物确定：

- 对具体对象的即时目标，使用行动动词表达
- 阻碍与失败代价
- 当前策略以及失败后切换的新策略
- 手上正在做的真实事务
- 重心、呼吸、步态、距离、地位和眼神生命
- 面具如何维持，以及什么具体事件让它裂开
- 对话中的倾听、抢反应、思考后再开口

把心理词翻译成行为。例如，不写“她悲痛”，而写“她把气息锁在胸口，拇指反复压住熄灭的手机屏幕，护士脚步靠近时才把下巴重新抬平”。

### 3. 设计导演调度

先锁空间，再定摄影：

1. 首帧是否已经包含所有必要人物。
2. 每个人的世界位置、画面位置、身体朝向、视线目标和与地标的距离。
3. 单一连续镜头或明确的受控多镜头。
4. 机位侧、拍摄距离、景别、视场结果、构图和运动。
5. 光源方向、曝光优先级、物理接触、声音和对白时点。

镜头运动必须有叙事动机：人物面具裂开时才推进；权力转移时才改变高度或距离；关键事件后优先拍目击者反应。不要用无动机的环绕、升降、推拉或随机切镜制造“电影感”。

### 4. 按节拍融合

为每个时间段同时写清：

- 人物当下策略和可见行为
- 对手如何提前反应或延迟反应
- 摄影机如何覆盖这个行为
- 道具、身体、环境的物理状态
- 对白或声音在何时发生

表演与镜头不分成两篇文章。全局表演锚点可以放在时间轴前，但具体转折必须回到相应时间段中。

### 5. 编译中文成品

默认采用 `templates/final-seedance-prompt-template.md` 的字段顺序，根据镜头复杂度删去无用标题。简单单镜头可写成紧凑自然段；复杂对白、多人物或多切镜使用清晰分段。

中文表达遵守：

- 直接、具体、可拍摄，优先短句和主动动词
- `@标签`、精确台词和用户规定的专名原样保留
- 台词使用用户提供的原语言，不擅自翻译或增写
- 影视术语可使用中文；必要的角度、距离和时间码保留数字
- 不先生成英文再翻译，不默认输出中英双语

### 6. 静默检查

输出前静默确认：

- 当前镜头所需人物是否第一帧就在正确位置
- 每个主要人物是否有目标、压力和可见策略，而不是只贴情绪标签
- 眼神是否有目标、眨眼和思考过程，倾听者是否持续活着
- 每次表演变化是否被摄影机看见，每次运镜或切镜是否有原因
- 时长能否容纳动作，身体和道具是否有重量、接触与惯性
- 视线、左右关系、轴线、光向、服装、伤势和道具状态是否连续
- 是否只有剧本规定的人说话，是否没有多余角色、标签、字幕和旁白
- 最终是否为简体中文成品提示词

发现问题就直接改写，不把检查结果输出给用户。

## 时长与节拍预算

| 可用时长 | 默认表演容量 | 导演策略 |
|---|---|---|
| 3–5 秒 | 一个动作状态或一个反应 | 单镜头，一个构图重点，避免情节转折 |
| 5–7 秒 | 一个核心行动 + 一次可见变化 | 优先连续镜头，最多一次克制推进或重构图 |
| 8–12 秒 | 两到三个清晰节拍 | 可使用一次有理由的切镜，或单镜头内完成距离变化 |
| 12 秒以上 | 按事件拆分，但每段只承担一个清晰任务 | 明确每次切镜和连续性；复杂事件优先拆成多个生成片段 |

时长预算优先于“把所有好点子都写进去”。模型无法在时限内完成的动作必须删减或拆镜。

## 输出规则

默认只输出最终提示词，不使用“分析如下”“优化说明”或自我评价。

用户明确要求以下内容时才附加：

- 分析、导演阐述或表演依据
- QA、风险点或修改说明
- 多个方案、不同机位或表演强度版本
- 英文版或中英双语版
- 人物长期表演母版、声音母版或项目连续性表

若关键信息缺失但可以安全推进，采用最保守的可拍摄假设。只有缺失内容会改变人物身份、剧情结果、参考绑定或空间逻辑时，才提出最多三个简短问题。

## 常见错误

| 错误 | 修正 |
|---|---|
| “愤怒地看着他”“悲伤地哭” | 写目标、压力、呼吸、手部事务、视线和策略变化 |
| 贴入完整150–220词人物母版 | 只提取本镜头相关的稳定习惯与触发行为 |
| 表演段和摄影段各说各话 | 在同一时间段绑定行为、反应和摄影覆盖 |
| 每个人同时转头、同时惊讶 | 让反应按人物注意力和利害关系错峰传播 |
| 镜头无理由环绕或推进 | 让机位变化由信息揭示、面具破裂或地位变化触发 |
| 第一帧先拍空景再等人物出现 | 除非用户明确要求，第一帧已包含必要主体和空间关系 |
| 为了完整把提示词写得无限长 | 按时长和生成难度保留最关键控制信号 |
| 默认输出英文 | 默认直接输出简体中文，英文只响应明确要求 |
