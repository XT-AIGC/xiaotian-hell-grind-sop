## 审计结论

| 现有规则/文件 | 处理 | 理由与边界 |
|---|---|---|
| 三路由、组件按需加载 | 共用 | 版本不改变是否需要前置资产；视频编辑/续接归视频路线，图片编辑仍归LIRA |
| planned→generated→accepted→uploaded→bound、真实标签 | 共用并扩展媒体类型 | 更多参考也必须验收与绑定，数量增加不等于职责放宽 |
| 唯一权威维度、身份/环境/动作/摄影隔离 | 共用 | 2.5 参考更多，仍不能让白模、场景、身份互相抢控制 |
| 角色目标、压力、倾听、可见反应和情绪残留 | 共用 | 这些是创作规则，不是模型参数；增强表现不保证每次成功 |
| 首帧、地图、轴线、视线、遮挡、道具与声音连续性 | 共用 | S1 仍承认复杂运动及多人交互的稳定性有改进空间 |
| 原组件 3–12 秒节拍建议 | 共用局部节拍 | 不把表演密度建议误当生成上限，不将30秒压缩成一个反应 |

| README / SKILL / 默认提示的最终2.0名称 | 总控分版本 | 未指定版本默认2.0；显式2.5用2.5标题与能力 |
| 两个内嵌组件及组件示例、模板、元数据 | 保留原文和哈希 | 不能仅靠新模型发布就宣称组件经2.5验证；版本覆盖只发生在总控 |
| 原始 iteration-1 eval 输出 | 保留历史2.0记录 | 新增版本用例，不倒填2.5成绩；Soul 2.0是图片模型名，不替换 |

## 版本与平台合同

先记录目标版本、目标平台、模式、请求时长、已确认入口能力；输出按用户选定版本标识。未指定版本默认 2.0；明确指定 2.0 时不自动升级。“最新版”需要确认，不能静默换成 2.5。缺少平台参数可先交付版本明确的草案，标记待确认能力；不得称为可直接提交的成品。

| 能力 | Seedance 2.0 | Seedance 2.5 |
|---|---|---|
| 单次时长 | 模型级基线15秒（S1对前版的比较）；实际入口可更短 | 模型级最长30秒（S1/S2）；实际入口可更短 |
| 多模态参考 | 已支持文字、图像、视频、音频（S3）；数量按入口核对 | 参考控制增强，模型级30图/10视频/10音频（S1）；不得给2.0套这个容量 |
| 续接 | 只采用已确认入口功能，不借用2.5轮数 | 按平台可用续接次数逐次提交、验收和重绑定源视频 |
| 编辑 | 保留已开放参考/编辑能力（S3），不称为“不支持编辑” | 时间戳定点音视频编辑、白模参考、绿幕/机位/参考编辑增强（S1/S2） |

平台不支持请求时：先给符合现有版本/入口的拆段、减少参考或后期处理方案；需要换版本时等用户明确选择。不能因请求30秒就把明确的2.0改成2.5。容量未知时不填猜测数字。

## 2.5 编译适配（总控规则，不是官方API语法）

1. 保留组件表演与空间设计，把最终标题设为 Seedance 2.5。仅覆盖版本专属名称、时长和能力边界，不覆盖真实素材、台词及共用规则。
2. 15–30秒按事件设时间轴，每段一个明确任务；时段连续、无重叠，结束不超过请求时长。是否切镜按叙事需要，一次生成不等于必须无剪切。短任务不强制加长到30秒。
3. 参考按媒体类型、实际标签、允许/禁止转移维度交接。白模可负责空间/姿态/轨迹/摄影；外观、材质、光线由已指定资产负责。创意参考仅继承用户指定的意图/构图/节奏，不能重塑人物。
4. 视频编辑先确认源视频、时间原点、目标区间、修改维度与保留内容；只改指定区间/维度，检查前后状态和音画连续性。绿幕替换还需校准环境光、影子与动作受力，不能自动扩大修改范围。
5. 续接先确认源视频的末帧位置、朝向、道具、情绪、动作和声音；新段时间码从0开始，另记其在整片的偏移。每轮完成后实际验收再上传绑定，不假设工具已生成或标签沿用。
6. 模型和平台设置在交接/提交说明记录，不把未经确认的API字段塞进自然语言提示词。无真实标签时仍停在绑定关；无引用需求的文生视频可直接写。

## 一致性与验证边界

生产入口（README、总控SKILL、默认提示）必须表达同一默认值和显式选择规则；2.0示例与历史记录继续有效。2.5示例明确平台能力前提，eval同时覆盖保留路径、新能力、未知入口、超限和无真实标签场景。

结构断言和规则审读不能代替真实模型执行。当前审计没有生成视频，没有证据宣称2.5实际成片质量或第三方平台已全部支持上述功能。
